# Spring Boot 后端 AI 代码审核规范

## 1. 审核范围

1. 以目标分支与当前提交之间的 Git Diff 为主要审核对象。
2. 阅读被修改代码的上下文，包括 Controller、Service、Mapper、Entity、DTO、配置文件和相关测试。
3. 追踪重要调用链，不能只根据单个方法判断正确性。
4. 不得把需求中未定义的业务规则当作既定事实。

## 2. 必须检查的项目

### Java 与 Spring
- 空指针、边界条件、异常处理和资源释放。
- 依赖注入、Bean 生命周期、AOP 代理和事务是否符合预期。
- `@Transactional` 是否存在自调用失效、传播行为不正确、异常未触发回滚等风险。
- 是否存在不必要的全局状态、线程安全问题或循环依赖。

### MyBatis 与 MySQL
- SQL 参数是否正确绑定，禁止通过字符串拼接构造不可信 SQL。
- 是否存在全表更新、全表删除、分页错误、N+1 查询和不必要的重复查询。
- INSERT、UPDATE、DELETE 是否符合业务约束。
- 事务边界是否正确，是否存在并发更新、重复提交和数据不一致风险。
- 索引、唯一约束、NULL 处理和数据库字段类型是否匹配业务。

### API 与安全
- 参数校验、权限控制、越权访问和敏感信息泄露。
- 接口幂等性、重复请求、超时重试和异常返回。
- 日志是否包含密码、令牌、个人敏感信息或数据库凭据。
- SQL 注入、命令注入和不安全反序列化等风险。

### 测试与回归
- 是否覆盖正常路径、异常路径、边界值和关键业务不变量。
- 是否需要增加单元测试、Mock 测试或真实 MySQL 集成测试。
- 是否破坏现有接口、数据库兼容性或其他模块。

## 3. 问题分级

P0：严重安全问题、重大数据破坏或其他灾难性风险。
P1：核心业务逻辑错误、越权、事务失效、严重并发或数据一致性问题。
P2：明确的功能缺陷、异常处理错误、性能问题。
P3：可读性、维护性和非关键优化建议。

## 4. 审核证据

每个问题必须提供：
- 文件路径及行号。
- 具体代码或调用链证据。
- 可复现的触发条件。
- 实际影响。
- 推荐修复方案。
- 对应测试建议。

不得仅凭猜测报告问题。无法确认的事项应标记为“待验证”，并说明缺少的证据。

## 5. 审核边界

- 默认只读审核，不直接修改源代码。
- 不得自行执行生产数据库写操作。
- 不得输出或上传密钥、真实用户数据及生产凭据。
- 不得为了通过测试而删除测试或放宽业务断言。
- 不得未经批准修改数据库迁移、权限、安全配置或公共 API。
- 需求不明确时提出问题，不得擅自编造业务规则。

## 6. 最终报告

输出总体结论、问题清单、测试结果、未验证风险及是否建议合并。
只将有证据支持的问题作为确认缺陷。
